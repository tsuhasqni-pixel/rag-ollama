# Folio — 汎用ローカル資料整理・検索 製品設計

更新: 2026-10-24 / 対象リポジトリ: rag-ollama

## 製品の主旨
Folioは利用者が持つ文章・資料・メモを自分の端末で保管し、言葉で検索して必要な箇所を見つける**汎用の独立アプリ**。利用者のデータの内容、家族構成、活動や目的をあらかじめ想定・限定しない。

## AIを使わない基本機能
- ローカルの文章とファイル（現状 .txt / .md / .csv / .json）を選んで登録。ファイルはテキストとして読み込み、元形式の複雑な構造解析を保証しない。
- 分類は「メモ・記録」「資料・書類」「数値・表」「その他」。日付（任意）・種類・キーワードで検索。
- 保存済み資料一覧と資料の個別削除。
- 本文はSQLiteへローカル保存、検索エンジンはOllama不要。
- 従来の分類名（過去の「日記」「家計簿」「子どもの記録」「仕事・学校」）がDBに存在する場合、本文・日付は残し、より汎用的な分類名へ移す。分類名だけの変更であり、文章は消さない。

## 任意のAI機能
- ユーザーが「検索結果から回答を生成する」を押したときだけ、検索上位の最大3件から抜粋をローカルOllamaへ渡す。
- 出典となる記録のID・日付・タイトル・カテゴリを画面に表示する。
- 回答の正しさは元の資料で確認する。資料にないことは推測しないようモデルに指示。生成結果の誤りを完全に防げる保証はない。
- 現状は語句一致の小規模検索（最大500候補を調査）。高精度な意味検索、PDF/Wordの解析、大量ファイル向け索引は未完成。

## 商品の独立性
- 他の個別アプリとの自動同期、専用バックアップのインポート、専用API連携は提供しない。
- .txt/.md/.csv/.jsonなどの通常ファイル取り込みだけを一般機能として提供する。入力形式に別アプリ固有の前提を置かない。
- 以前の開発候補にあった他アプリ専用の取り込み画面・エンドポイント・テストは削除済み。
- 過去にすでに登録された記録は、分類名を移し替えて保存し続ける。削除は利用者の明示操作時のみ。

## プライバシーと出荷前HOLD
- SQLite保存は現在**非暗号化**。端末の権限管理・ストレージ保護、バックアップと削除の仕様を販売前に仕上げる。
- アプリ内での削除は、OSバックアップやSQLiteの未使用領域を含めた完全消去を保証しない。
- Windows実機、正式Store Identity / Publisher、MSIX、WACK、実機Ollama正答率は別途必要。GitHubのWindows Actions PASSはその代用ではない。
- 他のアプリとの接続を予定や販売機能として紹介しない。利用例は特定の対象を限定しない。

## テスト項目
一般的な資料追加、カテゴリ・日付検索、AIなし動作、AIモックの根拠表示、個別削除、レガシーDBの分類移行、UIの水平はみ出しチェック。
